v0.3.6 — identité configurable et composition réutilisable

L’identité produit, les chronologies et les enregistrements de terminal se configurent sans copier les modèles du thème.

La version v0.3.6 réduit le besoin de remplacer les modèles du thème. params.brand configure la destination, le mot-symbole, les marques claire et sombre, ainsi que les icônes, tout en conservant les valeurs projectious.work par défaut.

Les partiels publics timeline.html et asciinema.html composent des feuilles de route, des phases et des galeries d’enregistrements à partir de données structurées. Le lecteur accepte aussi les options de commandes, d’ajustement et de palette. Le mode clair explicite réinitialise désormais toutes les couleurs de marque définies par le mode sombre.

Version v0.3.6 sur GitHub

v0.3.5 — sélection lisible et navigation opaque

Les surfaces sombres utilisent des couleurs de sélection accessibles et l’en-tête fixe reste distinct du contenu qui défile.

Avec v0.3.5, les variantes sombre profond et bleu nuit utilisent une sélection de texte très contrastée, avec un fond bleu marine et un texte clair. L’en-tête fixe possède désormais une surface entièrement opaque : le contenu ne transparaît plus sous les commandes de navigation pendant le défilement.

Version v0.3.5 sur GitHub

v0.3.4 — API publiques pour les composants pilotés par les données

Les sites peuvent composer badges, cartes, tableaux et shells applicatifs depuis les données Hugo avec des partials stables.

v0.3.4 fournit des partials stables pour les badges, listes de cartes, tableaux accessibles et shells applicatifs configurables. Les entrées de navigation peuvent représenter une section entière, le menu de versions accepte un libellé indépendant et le journal des modifications prend en charge les badges du frontmatter.

La documentation et l’exemple exécutable incluent également la règle security.exec.allow requise par Hugo 0.165+ pour tailwindcss.

Version v0.3.4 sur GitHub

v0.3.3 — fonctionnalités regroupées et exemples polyvalents

La documentation couvre désormais tous les shortcodes publics et de nouveaux exemples pleine page illustrent des usages au-delà de la documentation.

v0.3.3 facilite l’évaluation, l’apprentissage et l’adaptation du thème sans modifier ses contrats publics existants.

Documentation complète des fonctionnalités#

L’ancienne section Shortcodes fait maintenant partie de la section de référence Fonctionnalités. Chaque composant de contenu public dispose d’une page avec un rendu et un code source copiable.

Exemples de pages polyvalents#

La section Exemples comprend maintenant des compositions d’administration, de tableau de bord, de paramètres, de tarifs, d’état d’exécution, d’article et de journal des modifications. Les exemples opérationnels utilisent des interfaces d’application pleine page.

Navigation et historique des versions#

Les groupes de la barre latérale sont fermés par défaut, conservent leur état et proposent une commande compacte pour tout ouvrir ou fermer. L’ancien Blog a été remplacé par ce journal chronologique des modifications.

L’archive et sa somme de contrôle sont disponibles dans la version GitHub v0.3.3.

v0.3.2 — hooks publics pour les ressources du site

Les sites peuvent désormais ajouter leur CSS et leur JavaScript via Hugo Pipes sans remplacer les pipelines internes du thème.

v0.3.2 ajoute deux points d’extension rétrocompatibles.

hooks/styles-end.html ajoute le CSS ou SCSS du site et hooks/scripts-end.html son JavaScript. Les deux partials sont vides par défaut et s’exécutent après le pipeline du thème, avec Tailwind comme en mode Hugo seul.

Le guide de développement fournit des exemples à copier avec compilation, minification, empreinte et SRI. Aucune modification de configuration n’est nécessaire pour les sites existants.

L’archive et sa somme de contrôle sont disponibles dans la version GitHub v0.3.2.

v0.3.1 — design révisé et documentation complète du thème

Le design finalisé, des diagrammes fiables et une documentation multilingue complète arrivent dans cette version corrective.

v0.3.1 fournit l’implémentation finalisée du thème après la publication initiale de v0.3.0.

Système de design#

Les couleurs, la typographie, les élévations, le focus et les alignements suivent désormais le système de design projectious.work révisé. Les panneaux de code et de terminal sont adaptatifs et distincts, avec tous les rôles de syntaxe et les palettes de terminal de la marque.

Documentation#

Les sites anglais, allemand et français expliquent l’installation, la configuration, la création de contenu et de modèles, la maintenance, les dépendances et l’API publique du thème.

Corrections#

  • Les diagrammes Mermaid sont rendus et dimensionnés de façon fiable.
  • La barre latérale et la table des matières conservent leurs états séparés.
  • Les liens préservent langues, chemins de base, requêtes et fragments.
  • Les fonctionnalités sont classées par ordre alphabétique.

L’archive et sa somme de contrôle sont disponibles dans la version GitHub v0.3.1.

v0.3.0 — runtimes épinglés, recherche filtrée et palette de commandes

Les ressources sont versionnées précisément et la recherche indexe les titres.

KaTeX 0.18.4, Mermaid 11.16.1 et asciinema-player 3.17.0 utilisent des URL jsDelivr précisément versionnées. Les polices et les icônes restent incluses.

La recherche possède un enregistrement par page et par titre H2/H3. La palette de commandes, l’impression, les sorties Markdown, les liens d’édition multilingues et les métadonnées SEO complètent cette version.

v0.2.0 — mode sombre bleu nuit et accessibilité

Le thème ajoute plusieurs modes de couleur et des préférences de lecture persistantes.

Cette version introduit les modes clair, bleu nuit, sombre profond et système, ainsi que les réglages de taille du texte, contraste, focus, liens, mouvement et espacement. La navigation documentaire, la recherche et les composants Markdown ont également été stabilisés.
