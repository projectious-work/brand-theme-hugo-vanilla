Deploying your first pipeline

Define a pipeline, attach a policy check, and run it end to end.

Before you start#

You need a workspace with at least one connected agent, and the projectious CLI installed locally.

Define the pipeline#

pipeline.yaml 
name: onboarding-audit
trigger: on_document_upload
agent: auditor-v3
steps:
  - validate_schema
  - policy_check
  - deploy_staging

Add a policy check#

terminal 
$ projectious policy attach onboarding-audit --policy data-retention-v2

Policies are versioned. Attaching a new version does not affect runs already in progress.

Troubleshooting#

ErrorCause
SCHEMA_MISMATCHThe pipeline references a step missing from the agent manifest.
POLICY_NOT_FOUNDThe attached policy version was deleted or never published.
AGENT_UNREACHABLEThe agent lost its session token. Reconnect it under Settings.

Writing a policy

Express a rule set once, version it, and attach it anywhere.

Anatomy#

A policy is a named, versioned list of rules. Rules are evaluated in order and the first failure halts the run.

data-retention-v2.yaml 
name: data-retention
version: 2
rules:
  - id: pii_tagged
    assert: every_field_has_tag
  - id: retention_set
    assert: retention_days_between
    args: { min: 30, max: 365 }

Publishing#

terminal 
$ projectious policy publish data-retention-v2.yaml
✓ 2 rules validated
✓ Published as data-retention v2
