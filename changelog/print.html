v0.3.4 — public data-driven composition APIs

Consumers can compose badges, cards, tables and application shells from Hugo data through stable theme partials.

v0.3.4 turns the reference components requested by real consuming projects into stable theme interfaces.

Data-driven composition#

Public partials now render badges, card collections, accessible tables, and a configurable application shell from Hugo data. The existing badge shortcode delegates to the same public implementation.

Consumer navigation#

Primary menu entries can own a complete content section, the version selector can use an independent label, and changelog pages can render documented badge frontmatter. Compact headers automatically collapse the wordmark without removing the linked brand mark.

Reliable Tailwind setup#

Getting Started, the full configuration reference, and the executable example now include the Hugo 0.165+ security.exec.allow entry required for tailwindcss.

v0.3.3 — consolidated features and versatile examples

Feature documentation now covers every public shortcode, while new full-page examples demonstrate the theme beyond documentation sites.

v0.3.3 makes the theme easier to evaluate, learn and adapt without changing its existing public contracts.

Complete feature documentation#

The former Shortcodes section is now part of the authoritative Features section. Every public content component has a focused page with a rendered result and copyable source. The same structure is available in English, German and French.

Versatile page examples#

The Examples section now includes theme-native administration, dashboard, settings, pricing, run-state, article and change-log compositions. Operational examples use full-screen application shells to show how the design system works beyond the documentation layout.

Navigation and release history#

Sidebar groups default to closed, preserve reader state and provide a compact expand-all/collapse-all control. The former Blog has become this chronological Change log. Legacy links continue to redirect to their new locations.

Download the archive and checksum from the v0.3.3 GitHub Release.

v0.3.2 — public hooks for site-owned assets

Consuming sites can now append Hugo-piped CSS and JavaScript without replacing the theme's internal pipelines.

v0.3.2 adds two backward-compatible extension points requested by a project using the theme.

Asset append hooks#

Override hooks/styles-end.html to append site-owned CSS or SCSS and hooks/scripts-end.html to append progressive-enhancement JavaScript. Both partials are empty by default and run after the theme pipeline in Tailwind and Hugo-only builds.

The developer guide contains copyable Hugo Pipes examples that compile, minify, fingerprint and SRI-tag both assets. Existing sites require no configuration change.

Download the archive and checksum from the v0.3.2 GitHub Release.

v0.3.1 — revised design system and complete theme guidance

The finalized design system, reliable diagrams and comprehensive multilingual guidance arrive in this patch release.

v0.3.1 delivers the finalized theme implementation that followed the original v0.3.0 publication.

Design-system integration#

The theme now follows the revised projectious.work colour, typography, elevation, focus and alignment contracts. Code and terminal panels have separate adaptive surfaces, complete syntax weights and italics, readable text selection and branded terminal-recording palettes.

Documentation#

English, German and French sites now explain installation from scratch, site-wide and page configuration, content and template authoring, maintenance, dependencies and the public theme API. Feature pages cover accessibility, code, diagrams, editing, navigation, internationalization, notebooks, mathematics, search, tags, Tailwind, recordings, tokens and versioning.

Reliability fixes#

  • Mermaid diagrams render consistently and scale to their content.
  • Sidebar and table-of-contents highlighting remain independent while scrolling.
  • Links retain language prefixes, project base paths, queries and fragments.
  • Strong focus rings, token swatches, lists, file trees and print output use the intended design tokens.
  • Feature navigation and overview cards are alphabetized in each language.

v0.3.0 — pinned runtimes, section-filtered search, command palette

Runtime assets are version-pinned, search indexes headings, and every page action sits in one row.

This release makes runtime dependencies reproducible and reworks how readers move through a large documentation set.

Reproducible runtime assets#

KaTeX 0.18.4, Mermaid 11.16.1 and asciinema-player 3.17.0 load from exact jsDelivr version URLs. Fonts and the theme icon set remain bundled.

Search#

The index now carries one record per page and one per H2/H3, so a hit lands on the right anchor instead of the top of a long page. The /search page filters by section, and both inputs are debounced.

Page actions#

Copy as Markdown, view Markdown and print the whole section carry equal weight, so they share one row on docs pages, section indexes and release notes. The sidebar’s “Tools” group is gone.

Also in this release#

  • Command palette on Ctrl/Cmd K, shortcut help on ?, g+key jumps
  • params.codeTheme = "adaptive" for light code panels in light mode
  • Dark-mode image swapping, figure captions, scrolling wide tables
  • params.sidebarOpenDepth and a sidebar filter box
  • Announcement bar, outdated-version banner, back-to-top, mobile table of contents
  • Print styling, notebook conversion, multilingual edit links, SEO outputs

v0.2.0 — navy dark mode and the accessibility layer

Dark mode moves onto the midnight scale, and every accessibility setting became opt-in.

Navy dark mode#

Dark mode previously painted pages and cards on the terminal surface (#0e1720), which read as near-black. Page and card surfaces now sit higher up the midnight scale — #132440 and #1a2b3e — while code panels stay on the terminal surface, so a listing reads as recessed against the page around it.

The mode menu offers Light, Dark navy, Dark deep and System. System dark resolves to navy.

Accessibility selectors#

Text size, high contrast, strong focus ring, link underlines, reduced motion and loose text spacing are exposed in the header and persist per reader. Every setting is opt-in: nothing changes until the reader asks for it.

Fixes#

  • Accent text uses orange-11 on tinted rows, clearing AA
  • Card hover is a border and elevation shift, never an underline
  • The wordmark centres optically against the mark
